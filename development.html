How the code is organized

SealForge separates signing policy, storage, the interface and worker execution. When you change an API or shared contract, update its callers and tests too.

SealForge solution projects
ProjectResponsibility
SealForge.DomainEntities, job states and domain rules.
SealForge.ApplicationApplication contracts, interfaces and data transfer types.
SealForge.InfrastructurePersistence, storage and infrastructure implementations.

Prepare your development environment

With a local checkout, use the .NET 10 SDK and a Linux development environment. Docker Engine and Compose are needed for container-backed integration and local deployment work.

From the repository root, with the checkout's package sources configured:

dotnet restore SealForge.sln
dotnet build SealForge.sln --no-restore
dotnet test tests/SealForge.Tests/SealForge.Tests.csproj --no-restore

The full suite includes disposable PostgreSQL container tests. Run it against isolated resources, never a working deployment or a production database.

Choose the right evidence.

  • Use unit and component tests for policies, state transitions and UI behavior.
  • Use container-backed integration tests for real persistence and transaction behavior.
  • Use SoftHSM only as a software-token fixture; it does not prove a physical token and its driver work.
  • Validate real hardware, signing, timestamping and verification separately in an authorized environment.

The product's docs/development.md, docs/testing.md and docs/api.md contain the detailed development and integration instructions.

How to contribute

  1. Describe the change

    Explain the problem, current behavior and a small example that reproduces it.

  2. Keep related work together

    Follow the existing layers and update affected callers, tests and documentation.

  3. Share your test results

    Describe what you tested, and distinguish component tests from software-token and physical-token tests.

Keep sensitive information private

Never include API keys, token PINs, recovery codes, private keys, database dumps or identifying audit data in a public report. Share a minimal, redacted example instead.
