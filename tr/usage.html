SealForge’u Docker ile çalıştırın

Kendi denetiminizdeki bir Linux sunucuda linux/amd64 ve linux/arm64 için üç sürüm imajı.

İmajlar

  • docker.io/sealforge/web — web uygulaması ve REST API
  • docker.io/sealforge/worker-jsign — imzalama işleyicisi ve token erişimi
  • docker.io/sealforge/nginx — TLS ters proxy

Başlamadan önce

  • Docker Engine ve Compose 2.24.4 veya daha yenisinin kurulu olduğu, amd64 veya arm64 bir Linux sunucusu.
  • Uyumlu imzalama token’ı, sertifika ve worker imajıyla aynı mimari için derlenmiş PKCS#11 modülü.
  • Sunucu adınız için TLS sertifikası ve zaman damgası doğrulamasında kullanılan CA paketi.
  • Yedekleme planıyla birlikte kalıcı PostgreSQL ve dosya depolaması.

Kurulum

  1. Sunucuyu hazırlayın

    Kurulum dizinini oluşturun; TLS, PKCS#11 ve güven dizinlerini ve sürümün Compose dosyalarını ekleyin.

  2. Gizli bilgileri yapılandırın

    PostgreSQL ve worker veritabanı parolalarını ve genel adresi kurulum ortam dosyasında ayarlayın.

  3. Doğrulayın ve başlatın

    Sürüm notlarındaki sürüm etiketini ve üç imaj özetini yükleyin, imaj ön kontrolünü çalıştırın ve üretim kurulumunu USB token ek dosyasıyla başlatın.

  4. Kurulumu tamamlayın

    Kurulum sayfasını açın, web günlüklerindeki kurulum kodunu kullanın, yönetici hesabını oluşturun ve MFA kaydını tamamlayın.

  5. Token’ı kaydedin ve imzalayın

    Token’ı kaydedin, bir İmzalama İzni verin ve bir test dosyası imzalayın.

Hızlı başlangıç

export SEALFORGE_IMAGE_VERSION='<version>'
export SEALFORGE_WEB_IMAGE_DIGEST='<web digest>'
export SEALFORGE_WORKER_IMAGE_DIGEST='<worker digest>'
export SEALFORGE_NGINX_IMAGE_DIGEST='<nginx digest>'

bash deploy/scripts/verify-production-images.sh

docker compose -f docker-compose.yml -f docker-compose.prod.yml \
  -f docker-compose.usb.yml up -d

Sürüm notlarındaki etiket ve özet değerlerini kullanın; üretimde latest gibi hareketli bir etiket kullanmayın. Yayımlanan imaj dizini sunucunuzun platformunu içermiyorsa ön kontrol başarısız olur.

Yerel derleme

install.sh imzalı kaynak paketini doğrular ve yayımlanmış imajları çekmek yerine aynı üç imajı sunucuda derler. Kesin komut ve o sürümün özet değerleri için sürüm notlarını izleyin.

USB token tak-çıkar

Fiziksel token hotplug desteği için sunucuda systemd ve udev gerekir. Yardımcıyı bir kez kurun; kurulumu başlatırken USB ek dosyasını en sonda tutun:

sudo deploy/scripts/sealforge-hotplug-install.sh install

docker compose -f docker-compose.yml -f docker-compose.prod.yml \
  -f docker-compose.usb.yml up -d

Sunucudaki pcscd servisi okuyucuyu zaten kullanıyorsa, SealForge token’ı kullanırken onu durdurun. Sürüm kurulum betiği bu hotplug zincirini varsayılan olarak kurar.

Yerel TLS

Üretimde şuradaki sertifika ve anahtar kullanılır: certs/fullchain.pem ve certs/key.pem. Yalnız yerel demo veya laboratuvar için SEALFORGE_TLS_MODE=local-self-signed kendinden imzalı bir sertifika üretir.

SealForge'u kurun

Kurulum adımları

  1. Kurulumunuzu açın

    SealForge kurulumunuzun HTTPS adresini açın.

  2. İlk kurulumu tamamlayın

    Kurulumun başlangıç çıktısındaki kurulum kodunu şu adreste kullanın: /setup. Yönetici hesabını oluşturun ve TOTP MFA kaydını tamamlayın.

  3. Kurtarma bilgilerini güvenle saklayın

    Kurtarma kodlarını çevrimdışı tutun. Kendi hesabınız ve doğrulayıcınızla giriş yapın; yönetici hesabını ekiple veya derleme hattıyla paylaşmayın.

İlk imzalama işinden önce

  • Worker, uyumlu ara yazılımla hedef token'a erişebilmelidir.
  • Token'da uygun kod imzalama sertifikası ve karşılık gelen özel anahtar bulunmalıdır.
  • Zaman damgası ve güven yapılandırması hazır olmalıdır.
  • İsteği yapan kullanıcı veya API istemcisinin kullanılabilir İmzalama İzni olmalıdır.

Yönetici rolü veya envanterde listelenen sertifika, otomatik imzalama yetkisi vermez.

Token ve izinleri hazırlayın

Uygulama hassas değişiklikler için istediğinde taze MFA doğrulaması yapın.

Token'lar ve sertifikalar

  1. Yönetim → Token'lar bölümünü açın ve Token Ekle seçeneğiyle kaydı başlatın.
  2. Tara ve Seç ile hedef token'ı seçin.
  3. PIN'i tarayıcının şifreli PIN adımında tanımlayın.
  4. Doğrula ve Kaydet adımını tamamlayıp dönen sertifika envanterini inceleyin.

Kayıt, kimlik doğrulamalı ve sertifika içeren envanter gerektirir. Tek etkin token vardır; sertifikaları ayrı seçimlerdir, örtük varsayılan değildir.

Kullanıcılar, istemciler ve İmzalama İzinleri

Kişileri Kullanıcılar bölümünde, derleme hattı kimliklerini İstemciler bölümünde yönetin. İmzalama İzinleri bölümünde tek kullanıcı veya API istemcisi ile tek sertifika seçin.

API istemcilerine yalnız gereken kapsamları verin. Sertifika kullanımı ayrıca izin gerektirir. Sorumluluklar değiştiğinde izinleri gözden geçirin veya iptal edin.

Ayarlar bölümünde saklama ve işletim politikalarını yönetin. Betiğe PIN veya varsayılan sertifika seçici koymak yerine üretici ara yazılımını kurulumda erişilebilir tutun.

İmzalama işi oluşturun ve takip edin

  1. İşler sayfasını açın

    Bu, kişisel imzalama alanınızdır. Yeni İş ile gönderim penceresini açın.

  2. İmzalama izni seçin

    Hesabınıza verilen sertifika iznini seçin. Kullanılabilir izin yoksa yüklemeden önce yöneticiden yardım isteyin.

  3. Dosyanızı seçin ve imzalayın

    Kabul edilen dosyayı seçin, istenirse MFA doğrulamasını tamamlayın ve İmzala düğmesine basın.

  4. Sonucu kontrol edin

    İş satırındaki Ayrıntılar ile durum, tamamlanma ve hata bilgilerine bakın. Yardım isterken iş kimliğini saklayın.

İşleriniz ve sistem genelindeki işler

Kişisel İşler sayfası etkileşimli işlerinizi gösterir. Yöneticiler Yönetim → İşler bölümünde sistemin tamamını görür.

Tarayıcıdan indirme: İşler sayfasından istek gönderebilir ve işleri takip edebilirsiniz; dosya indirme henüz sunulmuyor. API indirme ucu yalnızca aynı API istemcisinin oluşturduğu işleri sunar. Sonuçları otomatik almak için aşağıdaki API akışını kullanın.

Derleme hattı akışı

API ile imzalamayı otomatikleştirin

Ayrı bir istemciyi submit, status ve download kapsamları ve açık bir İmzalama İzni ile oluşturun. Anahtarınızı derleme hattınızın gizli bilgi deposunda tutun.

1. İzni bulun ve gönderin

SEALFORGE_URL, SEALFORGE_API_KEY, SIGNING_PERMISSION_ID ve ARTIFACT_PATH değerlerini kendi kurulumunuza göre ayarlayın. İzin kimliğini ilk istekten alın.

curl --fail-with-body \
  --header "Authorization: Bearer ${SEALFORGE_API_KEY}" \
  "${SEALFORGE_URL%/}/api/v1/signing-permissions"

curl --fail-with-body \
  --header "Authorization: Bearer ${SEALFORGE_API_KEY}" \
  --form "artifact=@${ARTIFACT_PATH}" \
  --form "assignmentId=${SIGNING_PERMISSION_ID}" \
  "${SEALFORGE_URL%/}/api/v1/signing-jobs"

Başarılı gönderim, HTTP 201 ve şu alanı içeren iş bilgilerini döndürür: jobId. Bu kimliği sonraki istekler için JOB_ID olarak saklayın.

2. Sorgulayın, sonra doğrulanmış sonucu indirin

curl --fail-with-body \
  --header "Authorization: Bearer ${SEALFORGE_API_KEY}" \
  "${SEALFORGE_URL%/}/api/v1/signing-jobs/${JOB_ID}"

# Run only after status is ReadyForDownload.
curl --fail-with-body \
  --header "Authorization: Bearer ${SEALFORGE_API_KEY}" \
  --output signed-artifact \
  "${SEALFORGE_URL%/}/api/v1/signing-jobs/${JOB_ID}/download"

Başarısız, iptal edilmiş, engellenmiş veya süresi dolmuş işi başarısız sürüm adımı sayın. Yalnız gönderim başarılı diye indirmeyin. İndirilen dosyayı adlandırırken özgün dosya türünü koruyun.

İndirmelerde sahiplik ve saklama süresi denetlenir. İmzalama alanını kalıcı depo saymayın; sürüm kopyanızı kendi dosya deponuzda tutun.

İzin eksik mi?

Kullanıcı veya API istemcisinin ve iznin etkin, seçilen sertifikanın kullanılabilir olduğunu doğrulayın. API kapsamı, sertifika izninin yerine geçmez.

PIN veya token kullanılamıyor mu?

Yöneticiden token ve anahtar erişim ayrıntılarını incelemesini isteyin. PIN'i destek kaydı, URL sorgusu veya derleme hattı günlüğüyle göndermeyin.

API isteği reddedildi mi?

Bearer başlığını ve kapsamları kontrol edin; tam olarak bir geçerli assignmentId kullanın ve durum ile indirmede aynı istemci kimliğini koruyun. Bilinmeyen veya başka istemciye ait işler şu yanıtı döndürür: 404; izin verilmeyen veya hazır olmayan indirme ise: 403.

Daha fazla ayrıntı mı gerekiyor?

Kurulumunuzdaki /api-docs sayfasını ve işletim kılavuzunu inceleyin. Tanılama bilgilerini paylaşmadan önce kimlik bilgilerini ve kimlik belirleyen denetim verilerini ayıklayın.
