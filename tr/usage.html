Kullanım kılavuzu

Atölyeyi kurun.
Her adımın gereğini bilin.

İmzalama hedefini hazırlayın, açık erişim izni verin; işleri gönderimden son duruma kadar izleyin. Tarayıcı işleri ve API otomasyonu farklı kimlikler kullanır.

İlk kullanımYönetimTarayıcı işleriAPI otomasyonuSorun giderme

İlk kullanım yöneticiyle başlar.

  1. Kurulumu hazırlayın.

    Kurulum yönergelerini izleyin ve yapılandırdığınız HTTPS adresini açın.

  2. İlk kurulumu tamamlayın.

    Kurulumun başlangıç çıktısındaki kurulum kodunu şu adreste kullanın: /setup. Yönetici hesabını oluşturun ve TOTP MFA kaydını tamamlayın.

  3. Kurtarma bilgilerini güvenle saklayın.

    Kurtarma kodlarını çevrimdışı tutun. Kendi hesabınız ve doğrulayıcınızla giriş yapın; yönetici hesabını ekiple veya derleme hattıyla paylaşmayın.

İlk imzalama işinden önce

  • Worker, uyumlu ara yazılımla hedef token'a erişebilmelidir.
  • Token'da uygun kod imzalama sertifikası ve karşılık gelen özel anahtar bulunmalıdır.
  • Zaman damgası ve güven yapılandırması hazır olmalıdır.
  • İsteği yapan kullanıcı veya API istemcisinin kullanılabilir İmzalama İzni olmalıdır.

Yönetici rolü veya envanterde listelenen sertifika, otomatik imzalama yetkisi vermez.

Hedefi hazırlayın, sonra erişim verin.

Uygulama hassas değişiklikler için istediğinde taze MFA doğrulaması yapın.

Token'lar ve sertifikalar

  1. Yönetim → Token'lar (Admin → Tokens) bölümünü açın ve kaydı başlatın.
  2. Tara ve Seç (Scan & Select) ile hedef token'ı seçin.
  3. PIN'i tarayıcının şifreli PIN adımında tanımlayın.
  4. Doğrula ve Kaydet (Verify & Save) adımını tamamlayıp dönen sertifika envanterini inceleyin.

Kayıt, kimlik doğrulamalı ve sertifika içeren envanter gerektirir. Tek etkin token vardır; sertifikaları ayrı seçimlerdir, örtük varsayılan değildir.

Kullanıcılar, istemciler ve İmzalama İzinleri

Kişileri Kullanıcılar (Users) bölümünde, derleme hattı kimliklerini API İstemcileri (API Clients) bölümünde yönetin. İmzalama İzinleri (Signing Permissions) bölümünde tek kullanıcı veya API istemcisi ile tek sertifika seçin.

API istemcilerine yalnız gereken kapsamları verin. Sertifika kullanımı ayrıca izin gerektirir. Sorumluluklar değiştiğinde izinleri gözden geçirin veya iptal edin.

Ayarlar (Settings) bölümünde saklama ve işletim politikalarını yönetin. Betiğe PIN veya varsayılan sertifika seçici koymak yerine üretici ara yazılımını kurulumda erişilebilir tutun.

Tarayıcı işini gönderin ve izleyin.

  1. İşler (Jobs) sayfasını açın.

    Bu, kişisel imzalama alanınızdır. Yeni İş (New Job) ile gönderim penceresini açın.

  2. İmzalama İzni seçin.

    Hesabınıza verilen sertifika iznini seçin. Kullanılabilir izin yoksa yüklemeden önce yöneticiden yardım isteyin.

  3. Dosyayı seçin ve başlatın.

    Kabul edilen dosyayı seçin, istenen MFA doğrulamasını tamamlayın ve şu düğmeyi kullanın: İmzala (Sign).

  4. Sonucu kontrol edin.

    İş satırındaki Ayrıntılar (Details) ile durum, tamamlanma ve hata bilgilerine bakın. Yardım isterken İş Kimliğini (Job ID) saklayın.

İki iş sahibini ayrı tutun.

Kişisel İşler sayfası etkileşimli işlerinizi gösterir. Yöneticiler Yönetim → İşler (Admin → Jobs) bölümünde sistemin tamamını görür.

Tarayıcıdan indirme: İşler sayfasından istek gönderebilir ve işleri takip edebilirsiniz; dosya indirme henüz sunulmuyor. API indirme ucu yalnızca aynı API istemcisinin oluşturduğu işleri sunar. Sonuçları otomatik almak için aşağıdaki API akışını kullanın.

Derleme hattı akışı

Aynı API istemcisiyle gönderin, sorgulayın, alın.

Ayrı bir istemciyi submit, status ve download kapsamları ve açık bir İmzalama İzni ile oluşturun. Anahtarınızı derleme hattınızın gizli bilgi deposunda tutun.

1. İzni bulun ve gönderin

SEALFORGE_URL, SEALFORGE_API_KEY, SIGNING_PERMISSION_ID ve ARTIFACT_PATH değerlerini kendi kurulumunuza göre ayarlayın. İzin kimliğini ilk istekten alın.

curl --fail-with-body \
  --header "Authorization: Bearer ${SEALFORGE_API_KEY}" \
  "${SEALFORGE_URL%/}/api/v1/signing-permissions"

curl --fail-with-body \
  --header "Authorization: Bearer ${SEALFORGE_API_KEY}" \
  --form "artifact=@${ARTIFACT_PATH}" \
  --form "assignmentId=${SIGNING_PERMISSION_ID}" \
  "${SEALFORGE_URL%/}/api/v1/signing-jobs"

Başarılı gönderim, HTTP 201 ve şu alanı içeren iş bilgilerini döndürür: jobId. Bu kimliği sonraki istekler için JOB_ID olarak saklayın.

2. Sorgulayın, sonra doğrulanmış sonucu indirin

curl --fail-with-body \
  --header "Authorization: Bearer ${SEALFORGE_API_KEY}" \
  "${SEALFORGE_URL%/}/api/v1/signing-jobs/${JOB_ID}"

# Run only after status is ReadyForDownload.
curl --fail-with-body \
  --header "Authorization: Bearer ${SEALFORGE_API_KEY}" \
  --output signed-artifact \
  "${SEALFORGE_URL%/}/api/v1/signing-jobs/${JOB_ID}/download"

Başarısız, iptal edilmiş, engellenmiş veya süresi dolmuş işi başarısız sürüm adımı sayın. Yalnız gönderim başarılı diye indirmeyin. İndirilen dosyayı adlandırırken özgün dosya türünü koruyun.

İndirmelerde sahiplik ve saklama süresi denetlenir. İmzalama alanını kalıcı depo saymayın; sürüm kopyanızı kendi dosya deponuzda tutun.

Yeni yüklemeyle değil, iş durumuyla başlayın.

Yeniden göndermeden önce hata bilgisini inceleyin; token, izin veya güven sorununu yöneticinin gidermesini isteyin.

İş durumları ve sonraki yararlı adım
DurumYapılacak işlem
Queued / ProcessingWorker'ı bekleyin ve sorgulamaya devam edin. Gönderilmiş iş henüz imzalı sonuç değildir.
AwaitingAdminApprovalYönetici imzalama hedefini veya anahtara erişim koşulunu incelemelidir.
BlockedByTokenStateYönetici token/anahtar erişimini incelemelidir; tekrarlanan yüklemeler sorunu çözmez.
ReadyForDownloadDoğrulama başarılı. İşin sahibi API istemcisi, API işinin çıktısını alabilir.
FailedHata kodunu ve nedenini inceleyin, sorunu düzeltin; uygunsa yeniden gönderin.
Cancelled / Expiredİş, indirilebilir sonuç değildir. Yeni iş başlatmadan önce iptali veya saklama süresini inceleyin.

İzin eksik mi?

Kullanıcı veya API istemcisinin ve iznin etkin, seçilen sertifikanın kullanılabilir olduğunu doğrulayın. API kapsamı, sertifika izninin yerine geçmez.

PIN veya token kullanılamıyor mu?

Yöneticiden token ve anahtar erişim ayrıntılarını incelemesini isteyin. PIN'i destek kaydı, URL sorgusu veya derleme hattı günlüğüyle göndermeyin.

API isteği reddedildi mi?

Bearer başlığını ve kapsamları kontrol edin; tam olarak bir geçerli assignmentId kullanın ve durum ile indirmede aynı istemci kimliğini koruyun. Bilinmeyen veya başka istemciye ait işler şu yanıtı döndürür: 404; izin verilmeyen veya hazır olmayan indirme ise: 403.

Daha fazla ayrıntı mı gerekiyor?

Kurulumunuzdaki /api-docs sayfasını ve yetkili ürün işletim kılavuzunu kullanın. Tanılama paylaşmadan önce kimlik bilgilerini ve kimlik belirleyen denetim verilerini ayıklayın.
